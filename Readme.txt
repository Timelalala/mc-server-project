================================================================================
สรุปรายการแก้ไขและปรับปรุงระบบสำรองข้อมูล (Backup System)
================================================================================
วันที่ปรับปรุง: 17 ตุลาคม 2026

วัตถุประสงค์:
ปรับปรุงระบบสำรองข้อมูลเกม Minecraft และเปิดใช้งานปุ่ม Backup บนหน้าแดชบอร์ดแอดมิน
ให้สามารถกดสั่งสำรองข้อมูลรายโหนดได้จริง แสดงสถานะแบบเรียลไทม์ และเก็บไฟล์ถูกต้อง

--------------------------------------------------------------------------------
1. สคริปต์สำรองข้อมูลบน MC1: /usr/local/bin/mc-backup
   (ไฟล์ต้นฉบับใน repo: mc1-scripts-v4/installed-mc1/mc-backup)
--------------------------------------------------------------------------------
- รองรับการระบุ Server ID:
  * รัน `sudo mc-backup <id>` (เช่น `mc-backup 1`) เพื่อสำรองข้อมูลเฉพาะโหนดนั้น
  * รัน `sudo mc-backup` หรือ `sudo mc-backup all` เพื่อสำรองข้อมูลทุกโหนด (cron เที่ยงคืน)
- รองรับโหนด Local (MC1 - Java Survival):
  * จัดการกรณี host="local" และไม่มี user ให้บีบอัดไฟล์ลง /var/backups/minecraft/ โดยตรง ไม่ผ่าน SSH/SCP
- ค้นหาโฟลเดอร์เวิลด์ที่ถูกต้องตาม nodes.json:
  * อ่านค่า admin_world (เช่น world, World, DregoraRL) แทนการ hardcode "world"
  * รวมโฟลเดอร์เวิลด์ของผู้เล่นจากการจอง (w-user-*) เข้ามาในไฟล์ archive เดียวกัน
  * ลดขนาดไฟล์จากเกือบ 1 GB (ที่เคย fallback ไปบีบอัดทั้ง root directory) เหลือเพียง ~20-50 MB
- เพิ่มอ็อปชัน tar:
  * `--warning=no-file-changed` ป้องกันการ error กรณีเซิร์ฟเวอร์กำลังเปิดให้บริการอยู่
- ลบไฟล์ชั่วคราว /tmp/backup_node*.tar.gz บนโหนดปลายทางอัตโนมัติ

--------------------------------------------------------------------------------
2. Agent รับคำสั่งบน MC1: /usr/local/bin/mc-node-agent
   (ไฟล์ต้นฉบับใน repo: mc1-scripts-v4/installed-mc1/mc-node-agent)
--------------------------------------------------------------------------------
- เพิ่มคำสั่ง "backup" ในชุด ACTIONS ที่รองรับ
- เมื่อ backend จ่ายคำสั่ง backup เข้ามา agent จะเรียก `/usr/local/bin/mc-backup <server_id>`
- ดึงข้อความสรุปผล (พาธไฟล์และขนาด MB) ส่งกลับไปยัง Backend ทาง POST /api/mc/commands/:id/result
- รีสตาร์ท systemd service: `sudo systemctl restart mc-node-agent` พร้อมใช้งาน

--------------------------------------------------------------------------------
3. Backend API: mc-server-backend
--------------------------------------------------------------------------------
- controllers/nodeCommandController.js:
  * เพิ่ม 'backup' เข้าไปใน SUPPORTED set
  * ปรับเงื่อนไขการตรวจสอบ active booking: ให้แจ้งเตือนยืนยันเฉพาะกรณี 'stop' และ 'restart'
    ส่วน 'backup' สามารถทำงานได้ทันทีโดยไม่รบกวนผู้เล่นในเกม
- routes/index.js:
  * รองรับ POST /api/admin/servers/:id/backup (ผ่านคิวคำสั่งมาตรฐาน)
  * เพิ่ม Route Alias: POST /api/servers/:id/backup ตามที่ระบุใน requirement

--------------------------------------------------------------------------------
4. Frontend Dashboard: mc-server-frontend
--------------------------------------------------------------------------------
- src/pages/admin/Servers.jsx:
  * ปลดล็อกปุ่ม Backup (ลบ disabled={true} สีเทา) เปลี่ยนเป็นปุ่มสีม่วงนีออน
  * ผูก Event onClick ให้เรียก handleAction(s.id, 'backup')
  * กำหนด backupDisabled = allDisabled เพื่อให้กดสำรองข้อมูลได้ทั้งขณะเซิร์ฟเวอร์ Active หรือ Inactive
  * เพิ่มคำกริยาแสดงสถานะขณะทำงาน: "กำลังสำรองข้อมูล…" พร้อมไอคอนสปินเนอร์หมุน
  * แสดงแถบสถานะผลลัพธ์สีเขียวเมื่อเสร็จสิ้น: "✓ สำรองข้อมูล ... สำเร็จ: /var/backups/minecraft/... (XX MB)"
- ลบหน้า ยืนยันชำระเงิน (Payments):
  * ลบเมนู 'ยืนยันชำระเงิน' ออกจาก AdminSidebar.jsx
  * ปลด Route /admin/payments ใน App.jsx ให้ Redirect ไปที่ /admin/bookings
  * ลบไฟล์ mock Payments.jsx ออกจากโปรเจกต์

--------------------------------------------------------------------------------
5. อัปเดตเอกสารส่งมอบงาน: HANDOVER.md
--------------------------------------------------------------------------------
- อัปเดตข้อ 5 ในหัวข้องานที่เหลือ (ข้อความสถานะปุ่ม Backup) ว่าเชื่อมต่อระบบสำเร็จเรียบร้อยแล้ว

--------------------------------------------------------------------------------
6. ผลการทดสอบ (Verified)
--------------------------------------------------------------------------------
- โหนด 1 (MC1 - Java Survival): สำรองข้อมูลสำเร็จ ขนาด 52.2 MB ใช้เวลา ~2-3 วินาที
- โหนด 2 (MC2 - RLCraft): สำรองข้อมูลผ่าน SSH/SCP สำเร็จ ขนาด 27.4 MB
- สถานะคำสั่งในฐานข้อมูล/คิวคืนค่า 'done' ถูกต้อง

--------------------------------------------------------------------------------
7. ระบบแสดงผลข้อมูล CPU & RAM Usage แบบเรียลไทม์ (Admin Dashboard)
--------------------------------------------------------------------------------
- Backend API (GET /api/system/health):
  * พัฒนา endpoint ดึงข้อมูลสุขภาพโหนดจาก mc-node-health (ที่รันทุก 15 วินาที)
  * คืนค่า JSON สรุปการใช้ทรัพยากร: CPU Usage (%), RAM Usage (GB ที่ใช้ / ทั้งหมด),
    อุณหภูมิ (°C) และสถานะโหนด (active/online/offline) ของแต่ละโหนด (MC1, MC2, MC3, MC4)
- Frontend (src/pages/admin/Dashboard.jsx):
  * เขียนฟังก์ชัน fetchServerHealth() ดึงข้อมูลจาก /api/system/health
  * ใช้ setInterval(fetchServerHealth, 15000) ดึงข้อมูลอัปเดตทุกๆ 15 วินาทีแบบเรียลไทม์
  * แสดงค่าเฉลี่ยใน StatCard ด้านบน (CPU Usage, RAM Usage)
  * แสดงรายละเอียดแยกระดับโหนดในกล่อง Server Status (CPU, RAM, Temp ของแต่ละเครื่อง)
